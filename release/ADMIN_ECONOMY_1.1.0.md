# 경제 관리 업데이트 1.1.0

Minecraft 1.21.1, NeoForge 21.1.244 서버·클라이언트용입니다. 네트워크 프로토콜은 12입니다. 서버와 모든 친구의 클라이언트에서 기존 namanseulfarming JAR를 교체해야 합니다.

## 사용

- OP 2 이상: `/경제관리` 또는 `/economyadmin`. `/hub`의 경제 관리 버튼도 같은 서버 권한 검사를 받습니다.
- 일반 사용자: `/hub`에서 상점, 우편함, 프로젝트, 현황, 납품 의뢰를 엽니다.
- 관리자 화면의 분류 버튼으로 분류를 변경하고, 화살표로 작업을 선택합니다. 필드 화살표로 나머지 입력란을 확인합니다.
- 조회 결과 행을 누르면 해당 값이 입력란에 채워집니다. 변경 작업에는 사유가 필요하며 실행 전 확인 화면이 표시됩니다.
- 플레이어는 닉네임 또는 UUID로 지정합니다. 아직 서버에 접속한 적 없는 대상은 UUID를 사용하세요.
- 숫자 입력은 원 단위 정수입니다. 수수료·보상 비율 `0.02`는 2%, 추가 효과 `0.1`은 +10%입니다.
- 날짜는 `2026-10-10T20:00:00+09:00`처럼 시간대를 포함한 ISO 형식으로 입력합니다.

## 관리자 작업

| 분류 | 가능한 작업 |
|---|---|
| 지갑 | 잔액 조회, 지급, 차감, 직접 설정, 전체 등록 플레이어 지급, 경제 이용 정지 |
| 상점 | 상품 등록·수정, 구매·판매 가격, 재고, 재입고 수량·주기, 사용 중지 |
| 경제 설정 | 점검 상태, 수수료, 최소 수수료, 판매 수량 상한, 반대 거래 대기 시간, 동시 의뢰 수, 프로젝트 보상 비율, 지갑 상한 |
| 납품 의뢰 | 정책 등록·수정·모집 중지, 수락 내역 조회, 진행 의뢰 취소와 납품 아이템 반환 |
| 보상 | 퀘스트 보상 정책 금액·주기 변경, 특정 플레이어의 수령 제한 초기화 |
| 우편 | 조회, 돈·아이템 복구 우편, 전체 우편, 미수령 우편 취소 |
| 프로젝트 | 등록·수정, 완료·보상 발급, 취소·기여금 환불, 효과 변경 |
| 이벤트 | 등록·수정, 준비·활성·종료, 적용 구역·효과·기간 설정 |
| 구역 | 경험치·레벨 조정, 집중 구역 선택·해제 |
| 복구 | 원본 구매 영수증에 대한 1회 환불, 미완료 거래 조회·재시도, 등록 아이템 반환 |
| 기록·권한 | 원장·관리 작업 조회, 감사 기록 적체 확인, OP의 경제 작업 권한 범위 설정 |

권한 분류 입력값: `wallet,shop,rules,delivery,reward,mail,project,event,region,recovery,logs,permissions`. `*`는 전체입니다. 해당 권한을 지정하더라도 Minecraft OP 2 미만은 관리자 화면을 사용할 수 없습니다.

## 돈 지급과 원본 아이템 복구

돈 지급: 지갑 분류 → 돈 지급 → 대상, 금액, 사유 → 변경 확인.

원본 아이템 복구: 우편 분류 → 복구 우편 → 대상·수량 입력 → 관리자가 복구할 원본 아이템을 주 손에 듭니다 → 원본 데이터 복사를 켭니다 → 사유와 함께 발송합니다. 이름, 인챈트, 구성요소 데이터를 포함해 우편으로 수령합니다. 공간이 부족하면 전체 아이템 지급을 대기하며 땅에 버리지 않습니다. 원본이 없는 경우 아이템 ID로 기본 아이템을 발송할 수 있습니다.

등록 아이템 반환·미완료 거래 재처리는 대상이 접속 중이어야 합니다. 대상이 접속하지 않았다면 원래 요청을 유지하고 재시도합니다. 원본 데이터가 보관되지 않은 과거 아이템을 임의로 재구성하는 기능은 아닙니다.

납품 취소는 납품한 아이템 ID·수량을 반환합니다. 기존 납품 데이터는 원본 구성요소를 저장하지 않으므로 인챈트·커스텀 구성요소까지 복원하지 않습니다.

구매 환불은 관리자 보상 작업입니다. 실제 받은 아이템을 회수하거나 재고를 역산하지 않습니다. 원본 구매 영수증 하나당 한 번만 지급할 수 있습니다.

## 상품 등록

인벤토리 선택 후 수량·개당 가격을 따로 입력합니다. 가격은 1원 이상이며 기존 등록 가격을 바꾸려면 원본 등록을 취소한 후 다시 등록합니다. 같은 요청 번호에 다른 가격을 붙여 재실행할 수 없습니다.

상품 목록·인벤토리 선택에는 아이콘과 줄임 표시를 사용하고, 상품 목록은 마우스를 올려 전체 이름을 확인합니다. 아이템 이름 자체는 새 번역을 적용하지 않았습니다.

현재 플레이어 등록은 기존 개인 보관 등록 기능입니다. 다른 플레이어에게 공개하고 구매 대금을 정산하는 공개 거래소는 이 업데이트의 구현 범위에 포함되지 않습니다. 서버 관리형 상점 등록은 별도의 관리자 상점 작업을 사용합니다.

## 거래 보호와 기록

관리 변경은 요청 번호별 원본 결과를 저장합니다. 응답이 끊겨도 원래 요청을 재시도하며 추가 지급하지 않습니다. 관리자 요청은 플레이어 데이터에 저장해 재접속 후에도 복구합니다. DB 원장, 작업 사유, 감사 outbox는 같은 트랜잭션에서 저장됩니다.

백엔드 감사 파일: `/srv/mc/backend/logs/audit/integration-날짜.jsonl` (AUDIT_LOG_DIR로 변경 가능). 등록 아이템 감사 파일: 서버 월드의 `nfs-listing-audit`.

## 설치 순서

1. 서버 콘솔에서 `stop`으로 Minecraft를 저장 종료합니다. 기존 백엔드도 종료합니다.
2. 월드, `/srv/mc/backend`, PostgreSQL DB를 백업합니다. `.env`와 기존 연결 토큰은 그대로 보관합니다.
3. 업데이트의 Backend.zip을 기존 `/srv/mc/backend`에 덮어씁니다. `.env`는 묶음에 포함하지 않습니다.
4. 컨테이너에서 `cd /srv/mc/backend`, `npm ci`, `npm run migrate:admin`을 실행합니다. 001–022 스키마가 적용된 기존 서버 기준입니다.
5. 서버 `mods`의 기존 `namanseulfarming-*.jar`를 다른 폴더로 옮기고 새 JAR 하나를 넣습니다. 모든 클라이언트도 같은 JAR로 교체합니다.
6. PostgreSQL과 백엔드를 시작한 뒤, 기존 연결 환경 변수를 읽어 Minecraft를 시작합니다. 예시 명령은 설치 묶음의 안내문을 참고하세요.
7. 클라이언트 언어를 한국어로 선택하고 `/경제관리`를 실행합니다.

직접 게임에서 화면 클릭, 접속·재시작·인벤토리 복구를 확인하는 운영 테스트는 별도 체크리스트를 사용합니다. 자동 테스트와 컴파일은 실제 서버 배포 확인을 대신하지 않습니다.
