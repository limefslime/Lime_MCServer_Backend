# S2 납품 의뢰

## 사용

게임 허브 → **납품 의뢰**에서 다음 탭을 연다.

- 받을 수 있는 의뢰: 품목·필요 수량·완료 보상을 보고 수락한다.
- 수락한 의뢰: 수락 목록과 납품 진행 수량을 확인하고 보유 물품을 납품한다.
- 완료 기록: 최근 30개 완료 의뢰를 확인한다.

동시에 최대 3개를 수락할 수 있다. 납품 버튼은 메인 인벤토리의 일반 아이템을
남은 수량까지만 사용한다. 부족하면 일부만 납품하며, 이름 변경 등 사용자 지정
데이터가 붙은 아이템은 사용하지 않는다. 완료해야 지갑 보상을 받는다.
수락 목록·진행 상황·완료 기록은 DB에 저장되어 재접속 후에도 유지된다.

현재는 운영자가 설정한 의뢰다. MineColonies 창고 수요에서 자동 생성하거나
NPC가 창고 물품을 자동 출하하는 기능은 아직 구현하지 않았다.

## 설정과 설치

`config/delivery-contracts.json`의 예시 의뢰:

| 품목 | 수량 | 완료 보상 | 완료 후 재수락 대기 |
|---|---:|---:|---|
| 밀 | 64 | 70 | 24시간 |
| 대구 | 32 | 100 | 24시간 |
| Farmer's Delight 토마토 | 32 | 70 | 24시간 |

`DELIVERY_POLICY_PATH`로 외부 JSON 파일을 지정할 수 있다. 최대 30개 의뢰,
의뢰별 1~1,000개를 지원한다. 품목 ID는 설치된 아이템 ID여야 한다.
수락 시 조건을 저장하므로 설정을 수정해도 이미 수락한 수량·보상·쿨다운은 유지된다.

1. 기존 마이그레이션 021 다음에 `src/migrations/022_add_delivery_contracts.sql`을 적용한다.
2. 백엔드를 업데이트하고 기존 integration 토큰과 접속 주소를 설정한다.
3. UI 프로토콜 **11**의 모드를 클라이언트와 서버에 함께 설치한다.

Farmer's Delight × MineColonies 호환 패치는 제외했다. 확인한 0.1.6-alpha는
MineColonies 1.1.1367 이상을 요구하지만 원본 S2는 1.1.1319를 사용한다.

## 장애 복구

물품은 서버 플레이어 데이터에 납품 대기 상태로 저장한 뒤 HTTP로 전달한다.
응답 유실·백엔드 장애에서는 같은 요청 UUID로 재시도한다. 백엔드는 납품 진행,
완료 보상, 원장, 영수증, 감사 outbox를 같은 트랜잭션으로 처리한다.
확인된 거절에만 원본 물품을 반환한다. 인증 오류·불명확한 응답에서는 물품을
대기 상태로 유지한다. 대기 중에는 메뉴가 상태를 자동 갱신한다.

## 검증

자동 테스트: 수락/납품 재시도, 부분 납품, 완료 1회 지급, 소유자·품목·수량 검증,
잔액 한도, 감사 실패 롤백, 수락 조건 보존, Java 응답 검증.
PGlite 검증은 PostgreSQL 엔진을 사용하되 실제 DB 다중 연결 경합 시험과는 별개다.
백엔드 36개 테스트, Python 검증 3개(6개 Java 테스트 실행 포함), Java 21 컴파일과
모드 JAR 생성을 통과했다. 저장 메서드 접근 설정은 전용 서버와 싱글플레이 양쪽을 포함한다.

실제 게임 확인 항목:

- 허브 진입, 각 탭·스크롤·새로고침, GUI 배율별 표시.
- 수락 후 재접속, 일부 납품 후 재접속, 완료 시 보상과 기록 표시.
- 이름 변경 아이템 제외, 남은 수량 초과 소비 방지.
- backend 중단·응답 유실·서버 강제 종료 후 물품과 보상의 중복 처리 방지.
- 거절 후 인벤토리가 꽉 찬 경우 반환 대기와 공간 확보 후 복구.
